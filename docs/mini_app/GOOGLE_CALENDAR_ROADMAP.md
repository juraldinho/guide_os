# Guide OS — Google Calendar one-way import roadmap

> Зафиксировано: 2026-09-02  
> Статус: утверждённая будущая функция; реализация не начата  
> Направление: `Google Calendar → Guide OS` only

## 1. Цель и границы

Пользователь подключает собственный Google Calendar в профиле Guide OS, выбирает календари и видит их события в календаре Mini App. Импортированное событие является заготовкой: его можно открыть, дополнить стоимостью, статусом, оплатой, компанией, маршрутом и заметкой, затем сохранить как полноценный тур Guide OS.

Guide OS не создаёт и не изменяет события Google Calendar. Apple Calendar, iCloud, Exchange и другие провайдеры не входят в этот roadmap.

## 2. Утверждённые продуктовые правила

- подключение, календари, события и токены строго принадлежат текущему `user_id`;
- пользователь сам выбирает календари для импорта; рекомендуется отдельный календарь «Туры»;
- импортированное событие до преобразования блокирует дату/время, но не считается туром, не имеет дохода и не входит в статистику туров;
- событие можно открыть и преобразовать через существующую форму и `tour_service`;
- при преобразовании поля Google предзаполняют форму, пользователь дополняет и редактирует их;
- после сохранения создаётся обычный тур Guide OS, видимый и в боте, и в Mini App;
- преобразованный тур становится независимой записью Guide OS и не перезаписывается Google автоматически;
- связь с исходным Google event сохраняется для дедупликации и показа изменений источника;
- удаление непреобразованного события в Google удаляет/скрывает его импортированную заготовку;
- удаление исходного события не удаляет уже преобразованный тур;
- повторная синхронизация не создаёт дубликаты;
- интеграция должна иметь отдельный kill switch и не нарушать core-календарь при недоступности Google.

## 3. Владение полями

### До преобразования

Google управляет названием, датой, временем, all-day состоянием, местом, описанием и состоянием удаления. Guide OS хранит локальное зеркало только для чтения.

### После преобразования

Guide OS управляет всеми полями созданного тура: датами, временем, названием, компанией, маршрутом, стоимостью, оплатой, статусом и заметками. Изменения Google показываются как предложение для просмотра/применения и не затирают локальные данные.

## 4. Поэтапная реализация

### GC0 — продуктовый контракт

- утвердить окно первой загрузки (рекомендация: 90 дней назад и 365 дней вперёд);
- утвердить частоту фоновой синхронизации;
- утвердить визуальный статус импортированной записи;
- зафиксировать правила конфликтов, статистики, удаления и преобразования;
- обновить API contract до начала кода.

**Готово, когда:** нет неоднозначности между внешней записью, заготовкой и полноценным туром.

### GC1 — модель данных и миграции

Добавить отдельные user-scoped сущности:

- Google connection: владелец, Google account identifier, зашифрованный refresh token, scopes, status, timestamps/error;
- selected calendar: Google calendar ID, title, timezone, enabled, sync token;
- external event: calendar/event IDs, source fields, timestamps, deletion state, optional linked Guide OS tour ID.

Уникальность события: `user_id + google_calendar_id + google_event_id`. Существующую таблицу туров не использовать как зеркало Google.

**Готово, когда:** миграции идемпотентны, старые пользователи не затронуты, ownership и uniqueness покрыты тестами.

### GC2 — Google Cloud и OAuth

- отдельный Google Cloud project/client для соответствующего environment;
- включить Calendar API и настроить OAuth consent screen;
- использовать минимальные read-only Calendar scopes и offline access;
- OAuth code exchange выполняет backend;
- callback проверяет криптографически стойкий `state`, связанный с текущей Telegram session;
- client secret и refresh token никогда не попадают во frontend или logs;
- подготовить privacy policy и будущую Google OAuth verification.

**Готово, когда:** тестовый пользователь может безопасно подключить, переподключить и отозвать доступ.

### GC3 — backend API подключения

Добавить authenticated endpoints для состояния подключения, начала OAuth, callback, списка календарей, выбора календарей, ручной синхронизации и отключения. Все lookup/update выполняются с `user_id`; чужие connection/calendar/event IDs fail closed.

**Готово, когда:** токены не возвращаются клиенту, IDOR-тесты проходят, повторные запросы идемпотентны.

### GC4 — профиль Mini App

Раздел «Подключённые календари» показывает состояния: не подключено, подключение, подключено, синхронизация, ошибка, требуется повторная авторизация. Пользователь выбирает один или несколько календарей, запускает ручную синхронизацию и отключает интеграцию с подтверждением.

**Готово, когда:** полный connection flow работает в Telegram WebView и обычном браузерном callback flow.

### GC5 — первичная загрузка

- загрузить выбранное временное окно;
- корректно обработать pagination, recurring instances, all-day события, timezone, cancelled/deleted status;
- сохранить source fields без создания тура;
- не создавать дубликаты при повторном запуске.

**Готово, когда:** выбранные события стабильно появляются как внешние записи.

### GC6 — отображение и занятость

Импортированная карточка показывает Google source, календарь, название, дату/время, место и описание. Внешнее событие блокирует соответствующий интервал; all-day блокирует весь день. Оно не влияет на доход и tour statistics и визуально отличается от `reserved`, `confirmed` и `day_off`.

**Готово, когда:** календарь, month picker, day detail, conflicts и free dates учитывают внешний источник без двойного счёта.

### GC7 — преобразование в тур

Действие «Дополнить тур» открывает существующую форму тура с предзаполненными Google-данными. Пользователь добавляет стоимость, payment status, tour status, компанию, маршрут и заметки. Сохранение обязательно проходит через общий `tour_service` и существующие conflict/multi-day правила.

После успеха external event связывается с новым tour ID и перестаёт отображаться отдельной записью. Тур учитывается в доходе, статистике, уведомлениях, боте и Mini App.

**Готово, когда:** преобразование атомарно, повторное нажатие не создаёт второй тур, ошибка сохраняет введённый draft.

### GC8 — изменения и удаления источника

- непреобразованная запись автоматически следует изменениям Google;
- преобразованный тур не меняется автоматически;
- для изменённого источника показывается diff и явное действие «Применить изменения»;
- удалённый источник помечается, но связанный полноценный тур сохраняется.

**Готово, когда:** локальная стоимость и другие дополнения никогда не теряются при sync.

### GC9 — инкрементальная и фоновая синхронизация

Хранить Google `syncToken`, получать только изменения и удаления, обрабатывать pagination. Ответ `410` означает очистку sync token и безопасный full resync. Синхронизация запускается после подключения, вручную, при устаревшем состоянии на открытии и background worker. Нужны lock/pending guards для одного connection.

**Готово, когда:** sync повторяем, восстанавливается после ошибок и не запускает второй независимый SQLite writer.

### GC10 — конфликты и свободные даты

Внешние интервалы участвуют в общей проверке доступности. Преобразованное событие учитывается только как тур. Сообщение конфликта называет Google-событие и позволяет открыть/преобразовать его. Правило частично занятого дня должно совпадать с существующим availability contract.

**Готово, когда:** нет ложных свободных дат и двойной блокировки.

### GC11 — security и regression gate

Обязательны positive/negative/IDOR tests для connections, calendars, events, conversion и OAuth state; encrypted-token tests; отсутствие secrets в responses/logs; duplicate/replay tests; Google outage/degraded behavior; две реальные Telegram учётные записи; full backend/frontend suites и production build.

**Готово, когда:** чужие данные недоступны, HTTP 500 не маскируются permissive assertions, core Guide OS работает при выключенном Google.

### GC12 — закрытый пилот

Включить отдельным allowlist/feature flag для владельца и тестовых пользователей. Проверить OAuth возврат из Telegram, несколько календарей, recurring/all-day/timezone, преобразование, bot parity, update/delete, disconnect/reconnect.

**Готово, когда:** owner smoke и two-account isolation PASS с sanitized evidence.

### GC13 — публичный запуск

- завершить Google OAuth verification;
- проверить production redirect URIs, privacy policy и data deletion flow;
- настроить monitoring и recovery runbook;
- подтвердить encryption/secrets/log redaction;
- отдельный owner release approval.

Kill switch: `GOOGLE_CALENDAR_INTEGRATION_ENABLED=false`. Он скрывает подключение и останавливает sync, но не удаляет созданные Guide OS туры и не ломает бот/Mini App.

## 5. Первая версия: in / out

### In scope

- Google OAuth read-only;
- выбор календарей;
- initial + incremental sync;
- внешние события в календаре и конфликтах;
- карточка и преобразование в полноценный тур;
- отключение интеграции;
- user isolation, token protection, tests и kill switch.

### Out of scope

- запись из Guide OS в Google;
- редактирование Google events из Guide OS;
- автоматическое перезаписывание преобразованных туров;
- Apple/iCloud/Exchange/CalDAV;
- автоматическое распознавание любого события как тура;
- отдельная нативная iOS app.

## 6. Порядок начала будущей работы

Не начинать реализацию автоматически. Когда владелец явно активирует Google Calendar workstream, начать с GC0, провести audit текущего кода и создать отдельный пошаговый task. Не совмещать OAuth, migrations, sync engine и UI в одном изменении.

## 7. Смежный будущий roadmap

Дневные чаевые проектируются независимо от Google events и tours: одна сумма на пользователя и календарную дату. Они реализуются bot-first по `../TIPS_ROADMAP.md` и не входят в GC0–GC13.

GuideShop Mini App является отдельным активным workstream с собственными source/ownership правилами: `GUIDESHOP_MINIAPP_ROADMAP.md`.
